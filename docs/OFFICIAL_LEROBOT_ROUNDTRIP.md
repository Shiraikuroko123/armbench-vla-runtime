# Official LeRobotDataset round-trip

This integration pins the official `lerobot==0.4.4` distribution and its v3.0
`LeRobotDataset` API. It exports a local, image-backed three-frame episode and
reloads it through the official loader. The validator compares both lossless
PNG camera streams, the float32 state and action vectors, the task string, and
the episode-relative timestamp generated by LeRobot from `frame_index / fps`.

LeRobot 0.4.4 and ArmBench/OpenPI cannot share one Python environment:
LeRobot's `rerun-sdk` dependency resolves to NumPy 2, while the OpenPI path in
this repository pins NumPy 1.26.4. The project therefore does not expose a
`lerobot` optional extra. Create the isolated loader environment instead:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File `
  scripts\setup_official_lerobot.ps1

& '.\.venv-lerobot-0.4.4\Scripts\python.exe' -m armbench `
  vla-lerobot-official-smoke `
  --output-directory reports\official_lerobot_roundtrip_001

& '.\.venv-lerobot-0.4.4\Scripts\python.exe' -m armbench `
  vla-lerobot-official-validate `
  reports\official_lerobot_roundtrip_001
```

The setup script adds this checkout's `src` directory through a `.pth` file.
It deliberately does not register ArmBench's NumPy 1.26 package metadata in
the NumPy 2 loader environment, and it finishes with `pip check`. Do not run
OpenPI experiments in the LeRobot environment.

The Windows/Python 3.10 setup also constrains the ABI-sensitive packages to
the versions exercised here: NumPy 2.2.6, PyTorch 2.10.0, TorchVision 0.25.0,
Rerun SDK 0.26.2, Datasets 4.8.5, PyArrow 25.0.0, and PyAV 15.1.0. These pins
are kept in `scripts/official_lerobot_windows_py310_constraints.txt`.

The dataset declares `robot_type=panda_armbench_runtime`. Its state names are
seven Panda joint positions plus normalized gripper position, and its actions
are seven Panda joint velocities plus normalized gripper position. These are
not SO-101 joint-position commands. No Panda-to-SO-101 conversion, robot
driver, physical robot, learned policy, or hardware safety validation is
claimed. The artifact also binds the pinned loader version, action-semantics
SHA-256, and the current ArmBench adapter/watchdog implementation hashes.
