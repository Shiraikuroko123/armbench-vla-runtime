01 · ABSTRACT

VLA-Sync 究竟是什么？What exactly is VLA-Sync?

VLA-Sync 是一个针对 action-chunk VLA 推理延迟的可审计运行时与评测系统。它让策略推理与 20 Hz 控制时钟独立运行，记录观测年龄、响应生命周期与实际执行索引，再决定执行仍然有效的动作后缀或进入 fail-closed hold。 VLA-Sync is an auditable runtime and evaluation system for action-chunk VLA inference latency. Policy inference and the 20 Hz control clock advance independently; observation age, response lifecycle, and executed indices are recorded before a still-valid suffix is selected or the system enters a fail-closed hold.

它不是新的 VLA 模型，也没有训练 π0.5。项目通过 OpenPI 调用 Physical Intelligence π0.5 VLA 的官方 LIBERO checkpoint，研究异步闭环时序；同时保留从七自由度采样规划项目发展出的 MuJoCo Panda 运动学、连续碰撞、OSQP 投影和可行制动基座。 It is not a new VLA model and does not train π0.5. Through OpenPI, the project evaluates the official LIBERO checkpoint for Physical Intelligence's π0.5 VLA under asynchronous closed-loop timing, while retaining a MuJoCo Panda substrate for kinematics, continuous collision checking, OSQP projection, and feasible braking developed from the original seven-DoF planning project.

02 · MOTIVATION

VLA 输出一段未来动作，但响应到达时，这段“未来”已经过去了一部分。A VLA predicts a future action chunk, but part of that future has elapsed by the time the response arrives.

在 20 Hz 控制下，每 50 ms 就推进一个物理 tick。若推理耗时约 150 ms，直接从动作索引 0 开始执行，语义上等价于把基于旧观测的前三步再次施加到已经变化的系统。At 20 Hz, physics advances every 50 ms. With roughly 150 ms of inference, restarting at action index 0 replays the first three steps of an old observation onto a system that has already changed.

03 · METHOD

一个运行时核心，两条明确分开的证据轨道。One runtime core, two explicitly separated evidence tracks.

共享部分处理 provider、时钟、mailbox、动作语义、deadline 与审计；LIBERO 轨道测任务结果，Panda 轨道验证从七自由度规划项目继承的执行保障。The shared core handles providers, clocks, mailbox semantics, action meaning, deadlines, and attestation. The LIBERO track measures task outcomes; the Panda track validates the execution assurance inherited from the seven-DoF planning project.

R02 · CPU REPEATABILITY AUDIT

候选可行性与 fail-closed 发布可以重复；20 ms 原子执行不能。Candidate feasibility and fail-closed publication repeat; 20 ms atomic execution does not.

同一批 30 个冻结 π0.5 响应跨 3 个 Panda 场景，在 6 个独立冷启动进程中完整重跑。每轮均保持 66/90 个安全候选、0 不安全发布和 0 动作前缀泄漏；变化来自 best-effort Python 监督是否赶在 deadline 前结束。The same 30 frozen π0.5 responses and three Panda scenes are rerun in six fresh processes. Every trial retains 66/90 safe candidates, zero unsafe publications, and zero partial-prefix exposure; what changes is whether best-effort Python supervision finishes before the deadline.

v0.2.0 的单次最低规则 go 仍作为冻结记录保留，但空闲重跑为 [1,0,0]，受控 CPU 负载下为 [0,0,0]，因此当前不主张稳定或可部署的 20 ms 达标能力。The v0.2.0 single-run minimum-rule go remains a frozen record, but idle reruns are [1,0,0] and controlled-load reruns are [0,0,0]. Stable or deployable 20 ms compliance is therefore not claimed.

07 · ENGINEERING ROADMAP

已验证的系统结论与下一阶段工程改进Verified system findings and the next engineering improvements

现在已经证明Established today

  • 真实 π0.5 VLA checkpoint 能在独立推理/控制时钟下闭环运行。A live π0.5 VLA checkpoint runs with independent inference and control clocks.
  • 在冻结 120 对中，age-aligned suffix 的任务结果显著优于 response-relative chunk。Age-aligned suffix selection outperforms response-relative chunks in the frozen 120-pair study.
  • deadline 与离散控制 tick 的关系可通过 720 次多 suite/seed rollout 重现。The deadline/control-tick interaction reproduces over 720 multi-suite, multi-seed rollouts.
  • 从七自由度规划继承的 QP、连续碰撞和制动基座可由 CPU 独立重算。The inherited seven-DoF QP, continuous-collision, and braking substrate is independently recomputable on CPU.
  • 6 轮 CPU 重跑均保持 66/90 安全候选、0 不安全发布和 0 前缀泄漏；20 ms execute 在空闲与负载条件下均不稳定。Six CPU reruns retain 66/90 safe candidates, zero unsafe publications, and zero partial prefixes; 20 ms execution is unstable across idle and loaded conditions.

改进方向Improvement directions

  • 第二个真实 VLA checkpoint 家族，验证方法是否跨模型成立。A second real VLA checkpoint family to test cross-model generality.
  • 把 QP/连续碰撞/制动正式放入任务对齐的 VLA 在线闭环并做 no-repair 对照。Task-aligned online VLA repair with QP, continuous collision, braking, and a no-repair baseline.
  • 第二仿真器或真机复现；当前没有硬件安全、ROS2 或硬实时结论。A second simulator or real-robot replication; there is no hardware-safety, ROS2, or hard-real-time claim today.
  • 与 RTC、Action ControlNet 等直接方法在同一时钟与任务协议下的强基线。Strong direct baselines such as RTC or Action ControlNet under the same clocks and task protocol.
