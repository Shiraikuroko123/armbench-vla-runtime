02 / POLICY-TO-CONTROLLER BOUNDARY

一个动作块，五道检查，一次原子决策。One action chunk, five checks, one atomic decision.

碰撞检查没有被伪装成凸 QP 约束：OSQP 处理运动学可行域，投影后的每条线性关节边再由独立 checker fail-closed 验证。Collision is not disguised as a convex QP constraint: OSQP handles the kinematic feasible set, then an independent fail-closed checker certifies every projected linear joint edge.

07 / CLAIM BOUNDARY

现在能证明什么，也明确不能证明什么。What the project proves, and what it explicitly does not.

已有证据Evidence in hand

  • CPU 上完整动作块的时序、QP、连续碰撞与制动检查CPU temporal, QP, continuous-collision, and braking checks for complete chunks
  • 17/17 个 provider-neutral 异步边界案例可由 validator 重跑17/17 provider-neutral asynchronous boundary cases rerun by a validator
  • 拒绝时不泄漏已通过的局部策略前缀no accepted partial policy prefix leaks on rejection
  • 注册故障矩阵与两条 MuJoCo 力矩执行任务可本地重算locally recomputable fault matrix and two MuJoCo torque-executed tasks
  • 独立的官方 π0.5-LIBERO 观测年龄实验a separate official π0.5-LIBERO observation-age experiment

尚未声称Not claimed

  • Panda 任务源是 scripted RRT-Connect；异步矩阵只用 scripted、frozen 与 contract fixtures，没有执行 learned checkpointPanda tasks use scripted RRT-Connect; the asynchronous matrix uses scripted, frozen, and contract fixtures without executing a learned checkpoint
  • 任务是关节路点到达，不是抓取或物体操作tasks are joint-waypoint reaching, not grasping or object manipulation
  • 没有真机、硬实时、ROS2 或安全认证结论no physical robot, hard-real-time, ROS2, or safety-certification claim
  • 没有 π0.5 到 Panda 的端到端动作适配器no end-to-end π0.5-to-Panda action adapter

下一项真正需要 GPU 的研究步骤，是用至少两个冻结学习式 VLA 的输出替换 scripted source，并在同一异步任务协议下评测 supervisor。The next step that genuinely needs GPU access is to replace the scripted source with frozen outputs from at least two learned VLA families and evaluate the same supervisor under one asynchronous task protocol.
